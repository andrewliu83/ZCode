# Cua Driver 电脑操作接入（Community 0.1.7）

本次发行把 ZCode 的电脑操作从占位实现替换为固定版本的 Cua Driver 0.36.0，并扩展到三个桌面平台。

## 主要更新

- macOS、Windows、Linux 统一接入 Cua Driver 0.36.0，保存原有 `agent.computerUse` 工具入口与结果协议。
- macOS 由随包的独立 `CuaDriver.app` 承担辅助功能与屏幕录制授权；Windows/Linux 直接运行随包可执行文件。
- 会话隔离：每个 workspace/session 独立快照与元素 token，窗口带独占租约，驱动重启后旧 token 与旧截图立即失效。
- 截图坐标绑定真实 capture id 与栅格尺寸，不使用窗口边界或元素中心伪造目标。
- 权限查询走驱动自身报告，默认不弹系统提示、不抓屏；只有用户显式触发的功能探针才读取 AX 树或截图。
- 设置页区分“驱动不可用”“未授权”“未知”三种状态，授权后刷新沿用同一宿主。

## 后台输入

- 默认后台执行，不抢焦点。
- 原生控件直接通过 AX 写入。
- 网页内容（Electron/Chromium）拒绝 AX 后台写入时，先用当前截图坐标做后台像素聚焦，再输入文本或按键。
- 仅当驱动明确报告系统层无法后台投递时，才对该次动作短暂前台并恢复原前台；可用 `ZCODE_CUA_FOREGROUND_ESCALATION=never` 关闭升级。
- 无法等价保持的语义（选区、富文本剪贴板、强制 event/a11y 策略）返回明确错误，不伪造成功。

## 分发与安全

- 固定发行资产按官方 SHA-256 校验后解包，验证 Mach-O/PE/ELF 架构，资源位于 ASAR 外。
- SDK 依赖外置，按目标平台裁剪，只包含该平台原生包。
- 关闭 Cua Driver 遥测与独立自动更新；保留原始许可与第三方声明。
- macOS 原生资源使用专用权限 entitlements 单独签名；最低系统版本提高到 macOS 13。

## 发行修复

- 修复 Windows/Linux 构建前未准备 Cua Driver 资源导致打包失败：准备脚本现在按目标平台执行，并新增三平台门控回归。
- 修复 Windows checkout 换行转换改写随包许可导致摘要不一致：固定资源按原始字节入库。
- 修复 macOS “重启以更新”卡死：更新状态窗在下载/就绪阶段被锁为不可关闭，允许退出时没有重新同步，导致 `app.quit()` 被该窗口挡住、Main 不退出，安装助手等待父进程超时后放弃安装。现在允许真正退出时同步恢复可关闭状态，并在安装器接管后放行退出；失败安装残留的 staging 目录会在下次准备更新时清理。

## 验证

- 真实原生端到端通过：AX 树读取、窗口截图、设置值、点击后 DOM 读回、后台输入、按键、重启后旧凭据失效。
- `desktop-continuous` 与 `web-remote-replayable` 使用同一运行时，结果一致。
- 类型检查、Lint、架构检查与许可声明生成通过。
- Windows/Linux 已完成产物校验、架构检查与打包配置验证；两个平台的真实设备运行仍需在对应系统确认。

## 已知边界

- Windows/Linux 的 Chromium 网页内容在系统层拒绝后台键盘投递时，会按上述阶梯升级为短暂前台。
- Linux Wayland 的后台能力取决于合成器，X11 为完整支持路径。
- 遗留的 `@anthropic-ai/claude-agent-sdk` 平台包许可标识未在本版补齐，保持既有登记状态。
